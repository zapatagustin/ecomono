Explore intent and design for: $ARGUMENTS. No code until the design is agreed.

Runs inline. This is the one phase where shared context wins — the design lives in
the conversation, including the constraint mentioned in passing. Do not delegate it.

Rules: ONE question per turn, then STOP and wait. No option menus unless the fork
is real. Never agree without verification — wrong premise gets refuted with
evidence before anything is designed on top of it.

Sequence: restate the goal in one line → name the real constraint, reading the code
that already touches it → ask the one question whose answer changes the design →
propose one approach with its ceiling named → agree, then stop.

Output: goal, chosen approach, named constraint, what is explicitly out of scope.
If it needs "as we discussed" to make sense, it is not done. Multi-step work hands
off to `/ecomono-plan`; one edit gets implemented directly. Speculative scope gets
cut here with one line saying what and why.
